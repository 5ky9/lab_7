# АгроМаркет API

Подробные инструкции по запуску всего проекта, переменным окружения и настройке GitHub находятся в [README.md](../README.md).

## Локальный запуск API

Нужны Node.js 20+ и PostgreSQL. Можно поднять базу из корня проекта командой `docker compose up -d db`. Скопируйте `.env.example` в `.env`, задайте собственные `JWT_SECRET` и `ADMIN_PASSWORD`, затем в этой папке выполните:

```powershell
npm install
npm run db:init
npm run dev
```

`npm run db:init` пересоздаёт таблицы, загружает товары и создаёт администратора. Не запускайте её на базе с нужными данными.

## Маршруты

Все пути имеют префикс `/api`.

| Метод | Путь | Доступ | Результат |
|---|---|---|---|
| GET | `/health` | публичный | API и БД доступны |
| POST | `/auth/register` | публичный | Регистрация роли `user` |
| POST | `/auth/login` | публичный, rate limit | Вход и JWT |
| GET | `/auth/me` | JWT | Текущий пользователь |
| PATCH | `/auth/password` | JWT | Смена пароля |
| GET | `/products`, `/products/:id` | публичный | Каталог и товар |
| POST | `/products` | admin | Создание товара |
| PUT | `/products/:id` | admin | Изменение товара |
| DELETE | `/products/:id` | admin | Удаление товара |
| POST | `/orders` | публичный, JWT необязателен | Создание заявки |
| GET | `/orders/my` | JWT | Заявки текущего пользователя |
| GET | `/orders` | admin | Все заявки |
| PATCH | `/orders/:id` | admin | Изменение статуса |

Защищённые запросы должны содержать `Authorization: Bearer <token>`. Код `401` означает отсутствие/недействительность аутентификации, `403` — недостаточную роль.

## Краткие ответы к лабораторной

- bcrypt хранит необратимый, замедленный хэш с уникальной солью; проверка выполняется через `bcrypt.compare`.
- JWT состоит из header, payload и подписи. Payload не шифруется, поэтому секретные данные в него не помещаются. Изменение роли ломает подпись; компрометация `JWT_SECRET` позволяет выпускать поддельные токены, поэтому секрет нужно заменить и хранить вне Git.
- Обычная регистрация не принимает роль из запроса и всегда создаёт `user`.
- Скрытие административной формы в браузере — только UX. Защиту выполняет сервер через `requireAuth` и `requireRole`.
- Клиент хранит токен в `localStorage`, очищает его при выходе и прикладывает как Bearer. Это решение подвержено краже через XSS; в production следует рассмотреть `HttpOnly` cookies и меры защиты от CSRF.
- `401` — нужно войти; `403` — пользователь вошёл, но не имеет нужных прав.

## Postman

Импортируйте `postman/agromarket.postman_collection.json`. Задайте переменные `adminEmail` и `adminPassword` как в локальном `.env` и запустите коллекцию по порядку через Collection Runner. Токены сохраняются скриптами коллекции; предусмотрены проверки `401` и `403`.
